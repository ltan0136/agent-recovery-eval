# Benchmark Card

## 1. 测量目标

本评测检查工具调用系统在状态不确定、可重试与不可重试错误下的恢复行为，以及版本变更是否使原本通过的案例退化。它适合恢复机制开发、回归测试和评测基础设施学习。

本版公开业务步骤计划，重点在执行与恢复。它不单独测量端到端规划、开放世界搜索、真实用户满意度、通用智能或真实企业业务覆盖。

## 2. 数据与任务构成

| 维度 | 内容 | 解释 |
| --- | --- | --- |
| 工作流 | 工单通知、库存订单、会议预约、文档审核发布 | 不同业务状态与约束 |
| 业务变体 | 每个工作流的参数变化 | 是案例簇，不等于新增领域 |
| 调度种子 | 改变故障目标与调度参数 | 是相关重复条件，不是独立用户 |
| 条件 | clean、提交前超时、丢响应、延迟提交、陈旧查询、重复投递、限流、永久失败 | 人工安排的受控故障 |
| 手写基线 | 有界重试、查询后重试、幂等重试、不重试 | 已知行为的执行策略 |
| 模型被试 | 真实工具循环 runner 指定的模型与 revision | 与静态轨迹诊断单独记账 |

业务内容为程序生成的合成数据，示例身份使用保留域名和虚构字段。没有采集真实客户、公司内部工单、邮件或私人文件。

**本文件不固定填写一次运行的样本量和成绩。**以对应结果目录中的运行配置、JSONL 与元数据为准；README 中的结果只应来自真实运行，不从理论组合数推定“已经运行”。

## 3. 被测系统能看见什么

1. 业务请求、公开步骤计划、工具名称与参数规范。
2. 自己之前的工具调用、公共返回与公共错误。
3. 预算许可范围内的业务调用、查询、重试和停止动作。

被测系统不能读取内部故障标签、故障触发时刻、完整提交账本或评分答案。评分阶段才开放 oracle 状态。若适配器意外向模型泄露这些信息，该运行不能作为有效恢复评测。

## 4. 判定原则

先送达所有已调度的迟到写入，再检查最终状态及已提交操作记录。完整通过需要完成业务目标并满足相应约束；一句“已完成”、合法 JSON、工具 HTTP 成功或退出码为零都不能独立替代业务判定。

| 观察值 | 用途 | 应避免的误读 |
| --- | --- | --- |
| 任务成功 | 业务目标和约束是否同时满足 | 部分成功不能当完整成功 |
| 重复副作用 | 多余的写入、占用、通知或预约 | 不只数模型发起了几次调用 |
| 缺失效果 | 预期业务步骤是否未完成 | 少做操作也可能降低重复数 |
| 错误内容或关联 | 内容、对象、版本与引用是否正确 | “数量正确”不等于内容正确 |
| 工具调用量 | 恢复和查询开销 | 仿真调用量不等于生产成本 |
| 逻辑时钟 | 调度顺序和仿真等待开销 | 不能称为真实网络延迟 |
| 模型停止状态 | 正常停止、预算耗尽、模型/接口错误等 | 失败记录不能静默删除 |

永久故障可能使完整任务不可达。应同时查看停止行为、缺失和调用开销；不要以所有案例都必须成功为前提解释该条件。

## 5. 公平比较要求

1. 固定工作流、参数、种子、故障、工具契约和预算，用条件哈希确认版本间条件一致。
2. 模型比较另外记录模型名称、revision、采样参数、上下文与输出预算、运行环境和依赖版本。
3. 每种策略使用同一公共工具能力；稳定幂等键的收益必须归因到明确的服务端契约，不归因到隐藏的 oracle。
4. 原始格式错误、失败或被截断的回答都保留；如果使用修复器，另设实验条件并记录其额外成本。
5. 将无故障执行能力和故障恢复能力分别报告，防止把基础任务未学会误读为恢复机制失效。

## 6. 统计与版本回归

版本比较以相同冻结案例配对。主要关注通过变失败、失败变通过，以及重复、缺失和调用开销的变化。

置信区间使用配对簇 bootstrap：优先以 `(workflow, case_config.variant_id)` 为重采样单位，回退到明确 `variant` 或完整参数簇；保留同簇种子和故障条件，以及两版本的配对。每次抽取整簇，再计算案例加权完成率差。固定 500 次重采样与种子 0，默认 95% 百分位区间。缺少案例簇或不足 5 簇时返回 `insufficient_evidence`；5 簇是实现门槛，不代表达到这一数目便有充分统计把握。

门禁采用三种结论。任一案例的重复、缺失或错误成功声明变差时为 `block`；模型接口错误不排除出分母，并阻止统计放行；簇不足或区间跨过允许退化阈值时为 `inconclusive`。其余情况下，完成率差区间整体低于负的允许退化阈值时为 `block`，区间下界不低于该阈值时为 `pass`。`max_allowed_drop` 使用比例单位，例如 `0.02` 为 2 个百分点。

实现同时输出工作流、故障和二者组合切片。这些切片用于诊断，没有进行多重比较显著性校正。不能把其中最有利的一项当成事先声明的总体结论。

本套合成任务不是随机抽取的企业业务总体。即使区间窄，也只能支持预先声明的任务分布和实验条件内的结论。阈值或切片应先确定；不能在看完结果后选择最有利版本并照搬同一置信度解释。

## 7. 可复现材料

完整结果应包含以下材料：

1. 运行配置、代码版本、环境与模型元数据。
2. 案例标识与条件哈希。
3. 原始逐回合结果，包括失败和未完成状态。
4. 模型可见输入、原始模型输出与公共工具调用轨迹。
5. 结算后的业务状态、提交账本和判定理由。
6. 配对比较文件、统计参数与重放命令。

确定性模拟的重放是重新执行冻结案例；读取旧日志只是查看。真实模型的再次运行可能不同，须记录采样配置，不能把随机性隐藏成复现失败。

## 8. 已知限制与效度风险

1. 故障为人工、分阶段注入，不代表真实故障频率、相关性或长尾分布。
2. 工作流规模有限；公开步骤降低了规划难度，不能外推为自主规划成绩。
3. 幂等键、查询和等待语义由模拟器定义。现实工具可能缺少这些能力，或有不同一致性与保留时限。
4. 本地小模型样例只能验证运行闭环。小样本成绩不支持模型排名或产品选型。
5. 旧版 Prime 任务包测最终状态诊断，不能直接合并进动态恢复成绩。
6. Modal / Prime 的本地加载或 dry-run 不是云端评测结果；未运行项须明确标记。
7. 判定器本身也可能有错误，需要独立的已知答案、状态隔离和副作用测试。
8. 没有生产级安全、SLA、真实多服务事务或大规模并发保证。

## 9. 负责任的成果描述

可描述为“实现可复现的多工作流 Agent 恢复与回归评测工程”，并列出实际运行规模与真实发现。不能描述为“新通用 Benchmark 已获验证”“首创恢复算法”“所有 Agent 恢复率达到某值”或“已在云端和企业生产验证”，除非有另行公开的直接证据。
