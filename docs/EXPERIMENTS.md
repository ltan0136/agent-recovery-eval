# v0.2 实验记录

## 1. 冻结协议

规则矩阵固定为四工作流、每类 12 个业务参数变体、4 个调度种子、8 条件、4 策略，共 6,144 回合。每回合 24 次工具预算。种子选择故障步骤和延迟，不把它们当独立自然任务。

真实模型矩阵在查看成绩前固定：两个模型分别覆盖四工作流、一个参数变体、一个种子、clean／lost_ack、basic／guarded，共 32 回合。CPU float32、4 线程、greedy、160 个新 token、8 次模型请求、12 次工具调用和一次显式格式纠正。没有动态改提示、过滤失败或追加更有利的样本。

| 模型 | 固定 revision |
| --- | --- |
| HuggingFaceTB/SmolLM2-135M-Instruct | `12fd25f77366fa6b3b4b768ec3050bf629380bac` |
| Qwen/Qwen2.5-0.5B-Instruct | `7ae557604adf67be50417f59c2c2f167def9a775` |

模型收到公开步骤和工具规范，不收到故障标签及 oracle。低预算可能造成截断，因此必须联合检查 token 与停止原因，不能把全部失败归为恢复策略能力。两个小模型的结果只用于本地闭环检查。

## 2. 本轮结果

### 2.1 规则基线

正式执行 **6,144 回合**，1,536 个案例条件、48 个业务参数族、4 种工作流；每策略 1,536 回合。源码哈希在运行开始与结束一致。

| 规则策略 | 成功 / 回合 | 完成率 | 重复回合率 | 错误成功声明率 | 平均工具调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| no_retry | 330 / 1536 | 21.48% | 11.72% | 11.72% | 3.19 |
| bounded_retry | 600 / 1536 | 39.06% | 46.88% | 46.22% | 4.86 |
| verify_then_retry | 792 / 1536 | 51.56% | 35.16% | 34.77% | 5.38 |
| idempotent_retry | 1344 / 1536 | 87.50% | 0.00% | 0.00% | 5.25 |

每策略的 192 个永久失败案例全部未完成。幂等规则策略在其余 1,344 例通过，反映此服务端去重契约与策略的预期行为，不是语言模型恢复率或现实系统可靠性保证。无故障对照与故障切片见 JSON 快照。

独立只读审查从公开步骤、最终状态、提交账本、资源与依赖重算全部判分，未发现不一致；完整配置哈希复算一致。所有业务步骤均被故障目标覆盖。

### 2.2 配对回归

将 `idempotent_retry` 故意切换为 `bounded_retry`，比较 **1,536 对回合、48 个业务簇**，检出 **744 个退化、0 个改善**，门禁为 `block`。完成率差为 −48.4375 个百分点，探索性 95% 簇 bootstrap 区间约 [−49.22, −47.79] 个百分点。不是对企业业务总体的推断，也不是一次真实模型升级事件。

退化来源：丢响应 192、延迟提交 180、陈旧查询 192、重复投递 180。会议占位的容量约束会拒绝部分重复写入，所以后两类并非所有案例都退化。相同幂等策略自比较为 `pass`，完成率差及区间均为 0；这并不忽略其原有永久失败。

### 2.3 真实模型

正式完成 **32 个模型回合**，两模型各16例（clean8、lost_ack8）。这次没有完成整项业务的回合；所有原始失败都保留。

| 模型 | 业务成功 | 已存响应 | 工具调用 | 格式无效响应 | 截断响应 | 已存生成token | 实际触发lost_ack |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| SmolLM2-135M-Instruct | 0 / 16 | 32 | 0 | 32 | 32 | 5,120 | 0 / 8 |
| Qwen2.5-0.5B-Instruct | 0 / 16 | 93 | 75 | 18 | 2 | 2,865 | 6 / 8 |

1. Smol 的32条回答全部到达160 token上限且严格动作格式无效，未调用工具。因此不能把这些回合解释为实际遭遇写入故障后的恢复失败，也不能将截断全部归因为模型的业务诊断能力。
2. Qwen 已执行真实工具：`inspect_step`32次、`reserve_stock`21次、`hold_room`14次、`submit_document`8次。观察到重复查询、部分写入和重复副作用；独立判定共记录4个重复效果，完整任务仍为0/16。9回合因无效动作结束，7回合耗尽模型请求预算。
3. 两模型每个工作流／提示条件下的clean案例均失败。配对clean成功分母为0，**条件恢复率不可估计**；不能根据总体0完成率评判某种恢复机制的优劣。故障实际暴露与未暴露分开报告。
4. 已保存完整回合中的基础设施错误均为0；另有一次Qwen外部进程丢失，详见第4节。93条Qwen响应及token计数不包含未知在途尝试，不能当整个运行的精确总工作量。
5. basic／guarded各8例；小模型、四种合成流程与低生成预算只支持闭环和失败定位检查，不能支持模型排名。代表轨迹在HTML，全部记录在实验ZIP，轻量汇总见 `examples/release_snapshot.json`。

## 3. 复现

```bash
python scripts/reproduce_release.py --out runs/reproduction
python scripts/reproduce_release.py --out runs/reproduction-with-models --models --allow-download
```

第二条需要先安装 `requirements-local-model.txt`；离线时去掉 `--allow-download` 并提供 `--cache-dir`。脚本拒绝覆盖已有目录。耗时受 CPU 与网络影响；模型重新生成可能因底层数值环境不同而变化，不能只凭日志相同判断复现。

```bash
python scripts/verify_artifacts.py runs/reproduction/scripted
```

验证器核对文件校验和，并从全部原始回合重算 summary。GitHub CI 配置已提供；本地等价检查与 GitHub 托管 CI 的实际执行是两回事。

## 4. 运行中断与续跑边界

Qwen 首段在保存七个完整回合后发生推理进程丢失；内存记录无 OOM，退出原因未知。七个已保存失败逐字节保留，续跑仅按冻结案例键跳过这些已完成项，继续剩余九例；没有根据成绩选样。

中断时可能存在未落盘的在途尝试，其调用数、输出、工具状态和耗时未知，不能恢复为观测结果。最终报告中的模型响应、token 与工具量只统计完整回合的已保存记录，是整个运行工作量的下界；不据此比较模型时延或吞吐。正式分母为计划内32个完整回合，主机中断与早期工程调试另存。

提供固定发布协议的 Unix 回合级恢复工具（需要 fcntl）。先确认原 worker 已终止，再执行；已有完整失败不重跑，未知在途模拟回合从头开始。它不提供 token 级恢复或生产工具的精确一次保证。

```bash
python scripts/resume_model_run.py --source runs/model-qwen-release --out runs/qwen-recovered-new --cache-dir /absolute/path/to/hub --interruption-record runs/qwen_transport_interruption.json --one
```

包内正式结果已经完成，不要续写它们；上例使用新的输出路径。一次只增加一个完整回合；顺序重复至16例后自动结算成完整报告。工具要求源码、冻结计划、模型revision、预算和已保存前缀一致，并通过OS锁拒绝并发worker。它只支持本次发布协议，其他矩阵需另行扩展。

本次实际续跑脚本保存在原始本地提交 `b402658`，该提交仍在交付的 Git bundle 中；对应远程实现提交 `2f3262e8c18f2d4f4d8d7118388ca38b87a5fbe9` 与它具有相同 Git tree。对应脚本快照也随本地实验记录包提供，其SHA与续跑manifest匹配。发布源码之后加强了完整工作流与冻结配置校验并补上测试；这不改变14个评测核心模块或任何保存的模型结果。两个小模型曾并发推理，后续Qwen按回合重新加载；相关资源与中断事实一并保留。
