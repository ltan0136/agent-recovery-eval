## 3. 面试五问

1. **你到底测了什么？**
   测已知业务计划下的执行与故障恢复。模型读取完整公开步骤和工具契约，因此不能把结果解释成自主规划能力。四种工作流有不同状态约束，业务参数变体不等于新增领域。

2. **为什么返回成功还需要独立评分？**
   写入可能已经提交但响应丢失，重试会重复操作；迟到写入也可能在策略结束后到达。先结算这些效果，再检查业务状态与提交账本，才能识别漏做、重复和错误成功声明。

3. **幂等策略 87.5% 成功说明什么？**
   在固定任务集的 1,536 个回合中成功 1,344 个；其余 192 个为目标操作持续不可用的永久失败。这个结果主要验证服务端幂等契约及规则策略实现，属于构造环境下的基线检查，不证明 LLM 更聪明，也不证明现实系统具备恰好一次保证。

4. **744 个退化是不是模型升级造成的？**
   不是。它来自有意把幂等规则策略换成有界重试，检验门禁是否发现已知危险变更。比较保留相同条件并按工作流与业务变体成簇；48 个簇不能被扩写成 1,536 个独立任务。门禁通过也只对冻结任务集和预设阈值成立。

5. **Codex 做了什么，你做了什么？**
   如实说明 Codex 辅助了哪些代码、测试和文档，再列出本人实际完成的需求判断、实现修改、审查或复现。尚未亲自检查的部分直接说明。建议准备一个能现场重放、解释原因并修改验证的案例，以证明理解和工程掌控。
