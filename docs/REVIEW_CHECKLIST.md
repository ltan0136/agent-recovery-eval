# 审查清单

用于提交 GitHub 前的本地审查，以及拉取请求中的复核。勾选代表审查者已检查相应证据；未经检查不要预先勾选。

## 1. 快速审查顺序

1. 阅读 README 的实跑结果、测量范围和限制。
2. 阅读 [Benchmark Card](BENCHMARK_CARD.md)，确认任务分布、可见信息和评分边界。
3. 运行 README 的无密钥复现命令，并打开生成报告。
4. 选一个无故障、一个丢响应、一个延迟提交和一个永久失败案例，核对原始轨迹、业务状态与判定。
5. 阅读对应代码和测试，再决定是否接受功能或成绩描述。

## 2. 代码与可执行性

1. [ ] 全新 Python 环境中可按文档运行核心实验，依赖与可选组件清楚分开。
2. [ ] 四种工作流具有不同状态和约束，业务参数变化没有被冒充为新增工作流。
3. [ ] 工具参数被严格校验；未知操作和非法输入不会产生未记录的业务写入。
4. [ ] 每回合状态隔离；任务重置、迟到写入与确定性重放符合约定。
5. [ ] 所有关键故障均有直接测试，并验证失败情况，不只验证快乐路径。
6. [ ] CLI 的非零退出码、比较门禁和输出目录行为与文档一致。

## 3. 判定器与数据完整性

1. [ ] 已知正确、重复、缺失、错误内容和错误关联样例得到预期判定。
2. [ ] 判定前结算迟到写入；判定重复调用不会继续改变状态或影响其他回合。
3. [ ] 模型或策略声称成功，最终状态失败时被单独识别。
4. [ ] 原始失败、截断、无效输出、预算耗尽与接口错误保留，不静默排除。
5. [ ] 原始结果与报告计数一致；没有手工改成绩或用理论组合数代替实际执行量。
6. [ ] 案例、配置哈希、代码版本和模型元数据足以追溯对应运行。

## 4. 模型与基线边界

1. [ ] 手写策略、测试用顺序适配器、静态诊断和真实模型执行分别标记。
2. [ ] 真实模型原始输入、输出、工具参数与公共返回可审查。
3. [ ] 模型没有收到故障标签、内部账本、评分答案或未来写入调度。
4. [ ] 模型公开获取完整步骤计划这一点已在文档说明。
5. [ ] 所有模型请求及格式重试都计入预算；没有隐含免费的额外模型调用。
6. [ ] 声明的模型 revision、采样、生成上限和硬件与结果记录一致。
7. [ ] 幂等策略优势归因到正确使用服务端契约，未描述为模型智能的证明。

## 5. 版本比较

1. [ ] 案例集合、条件哈希、工作流和种子完全配对；不匹配数据被拒绝。
2. [ ] bootstrap 按工作流与业务变体成簇，未把相关种子和故障当作独立样本。
3. [ ] 簇不足或有模型接口错误时，不给出可靠放行的暗示。
4. [ ] 重复、缺失和错误成功声明的逐案例退化被审查，总体完成率没有掩盖严重退化。
5. [ ] 阈值、区间、样本量和切片写清楚；`pass` 只解释为本冻结任务集的门禁结果。
6. [ ] 故意策略变更得到的退化没有被写成真实模型升级事件。

## 6. 接口、云端与安全

1. [ ] MCP 客户端通过真实 stdio 子进程交互；不是仅直接调用 Python 函数的单元测试。
2. [ ] MCP 公共工具未暴露任意文件、命令或完整评分 oracle。
3. [ ] Modal / Prime 运行状态准确；本地加载与 dry-run 没有标成云端成功。
4. [ ] v0.1 的静态诊断适配器没有被描述成已兼容全部 v0.2 恢复任务。
5. [ ] 无 API key、登录令牌、个人文件、真实业务数据或私有环境信息进入提交包。
6. [ ] 所有业务副作用都在本地模拟，通知、付款和邀请不会送到真实系统。
